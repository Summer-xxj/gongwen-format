# 公文函件主体格式校验清单

## A. 输入与版式识别

- [ ] 已获得当前函件正文、收文机关、署名机关、成文日期、附件信息及拟用 Word 模板。
- [ ] 已确认采用信函格式首页还是公文通用格式；没有把“文种为函”自动等同于“信函格式”。
- [ ] 用户未提供的事实字段已列为待补，没有从历史样本复制名称、日期或事实。
- [ ] 已区分国标要求与单位模板约定。

## B. 主体文字版式

- [ ] 标题居中；通用格式标题字体字号/红线下位置正确；信函格式按信函首页模板定位。
- [ ] 多行标题断行不割裂词意，排列匀称。
- [ ] 主送机关在标题下空一行、左顶格；末尾为全角冒号。
- [ ] 正文首页可见（适用通用正文首页规则时）。
- [ ] 每个自然段首行左空二字，段内换行顶格。
- [ ] 正文字体字号按一般标准或用户模板；未把标准中“一般”要求误写成绝无例外。
- [ ] 层级序号、层级字体应用合理且一致。

## C. 附件及落款

- [ ] 仅在确有附件时标“附件：”；说明前空一行、左空二字。
- [ ] 多附件序号为阿拉伯数字；名称与附件页标题完全一致；名称末尾无标点。
- [ ] 署名、印章、日期按单一/联合行文以及盖章/不盖章的对应规则排布。
- [ ] 成文日期为阿拉伯数字完整日期；年份写全称，月日不补零。
- [ ] 签章、署名机关及日期均有用户来源或模板来源，不凭样本推测。

## D. 页码与整份文档

- [ ] 已先确定格式类别。
- [ ] 通用公文页码按第 7.5 条检查；附件与正文一起装订时页码连续。
- [ ] 信函格式首页不显示页码；续页编号方式依据实际模板/正式图示核验，不推断整份都无页码。
- [ ] 信函格式版记不加印发机关、日期和分隔线（如适用）。
- [ ] 页面、分节、首首页不同、奇偶页、附件分页等 DOCX 设置已核验。

## E. 导出检查

- [ ] 已用实际 Word 模板/文档处理流程落版，而非只靠提示词生成纯文本。
- [ ] 已导出 PDF 并逐页检查分页、行距、缩进、页码、签章区和附件起始页。
- [ ] 若无法编辑或渲染文件，明确标注未完成的版式检查项目。
- [ ] 已交付格式问题清单，注明条款和可执行修改建议。

## F. 本机 DOCX 程序化核验（WorkBuddy 环境，细则见 docx-audit.md）

- [ ] 已判断文档类型：方案/报告类（基础核验）或红头函件类（加做 G 节全套）。
- [ ] 字体核查同时覆盖系统目录与 WPS 目录（Win: `%APPDATA%\kingsoft\office6\docerFonts\`；macOS: `~/Library/Containers/com.kingsoft.wpsoffice.mac/Data/.kingsoft/office6/docerFonts/` 与 `data/fonts/extend_font/`），未把「系统目录缺失」误判为「环境无此字体」，也未在字体已在本机时让用户去下载。
- [ ] 字体真实家族名已用 pymupdf 读 name 表确认（文件名≠家族名，如 `方正小标宋_GBK.ttf` → `FZXiaoBiaoSong-B05`）。
- [ ] 判定序号「缺失」前，已核对段落自动编号属性（is_numbering / w:numPr）或向用户索取渲染截图。
- [ ] 全部结构性标题已设「与下段同页」（keep_with_next），未用段前分页替代。（排版建议，非国标条文）
- [ ] 正文数字、日期、序号数字与英文（西文）字母/单词均为 Times New Roman（与相邻中文同字号，英文内部标点保持原文半角）。（通行惯例，非国标强制；单位模板优先）
- [ ] 属性修改结果已落盘并解压 XML 验证，未仅凭工具读回值下结论（读回值可能误报）；editor_sdk 失效项已改用 XML 直接手术。
- [ ] 页码三件套已程序化核验修复（docx-audit.md §11）；红双线位置、实际分页、印章位置已列入人工 PDF 目视项，未宣称程序级通过。

## G. 红头函件专项（主送+落款+附件齐全时必查，细则见 docx-audit.md §7–§13）

**标题断行（国标 7.3.1，格式项不是内容项）**
- [ ] 长标题（22 字上下）已按词意主动手动分行，上长下短梯形排布；「的函」未孤尾两字。
- [ ] 正文未动的前提下，标题断行仍已调整（正文不动 ≠ 断行不动）。
**间距模型**
- [ ] 全文段前段后=0；28pt 固定行距段落 **100% 显式 `beforeAutospacing=0 / afterAutospacing=0`**（含主送段、空段、附件页段、分页空段——逐段扫 XML 确认，一个不漏）。
- [ ] 文档网格 docGrid 已清除（或确认无 lines 类型网格）。
- [ ] 段与段之间视觉间距 = 段内行距（主送机关与正文第一行之间不空行，国标 7.3.3）。
- [ ] 空段数量已逐个数：落款上方、附件说明前均**只空一行**（28pt），无多余空段（实际教训：原稿空 3 行被漏改）。
**隐藏字符**
- [ ] 全文 `&#13;`（软回车）计数 = 0（XML 层扫描；「某行后莫名多空一行」九成是它）。
**落款**
- [ ] 已向用户确认盖章 / 不盖章版式。
- [ ] 盖章版：日期右空四字；署名在日期上方**中心对称**（两段同一左缩进 + jc=center，勿用右缩进差值法）。
- [ ] 落款上方空一行且仅一行（28pt 空段）；署名段尾无软回车。
**附件页**
- [ ] 附件说明：正文下空一行、左空二字；名称与附件页标题一致。
- [ ] 「附件：」顶格黑体；附件标题居中；**另面编排**（附件：前有分页符，分页空段也是 28pt-exact）。
- [ ] 附件正文统一仿宋_GB2312（含纯中文 run 的西文槽位）。
**页码三件套（已程序化，docx-audit.md §11）**
- [ ] 格式 `— N —`（一字线）；宋体四号非加粗；单页码右空一字、双页码左空一字（奇偶分设）。
- [ ] 信函格式首页不显示页码：`titlePg` + 首页页脚为空；footer XML 已重写并落盘验证。
**红色双线（信函格式首页，docx-audit.md §12）**
- [ ] 上双线**上粗下细**（标志图下 4mm：2.25pt + 0.75pt）、下双线**上细下粗**（距下页边 20mm：0.75pt + 2.25pt）、总长 170mm 居中；已用 DrawingML 绘制并删除旧 PNG 单线 run。
- [ ] 线与标志图的间距已经用户目视确认（估算值可能偏 1–3mm，改 posOffset 微调）。
